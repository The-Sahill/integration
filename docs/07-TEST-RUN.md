## صيغة ردود زائر الفعلية (تم التحقق منها)
**`GET /reservations`**
```
{ status, result: { items: [...] }, count, page, limit (أقصى 250), totalPages }
item: { id, number: "REV2026125", reservation_status: confirmed|cancelled|checked_in|checked_out|unconfirmed,
        payment_status: unpaid|paid|partially_paid, booking_source: walkin|ota|booking_engine, booking_id,
        check_in_date, check_out_date, nights, guest: {name, phone}, rooms: [{unit_type_id, unit_id, unit_name, amount, daily_rates}],
        finance: { total, paid, balance_due, ... }, currency }
```
- **لا يوجد تاريخ إنشاء** (`created_at`).
- **فلاتر تعمل من جهة زائر**: `booking_id`، `number`، `guest_phone` (جزء من الرقم)، `reservation_status`، `booking_source`.

**`POST /reservations/quote`**: `{ available, rooms: [{ amount, available, available_count, rate_plan_id, daily_rates: [{date, unit_price, discount_amount, final_price, subtotal, lodging_fees, vat, tax_amount, final_amount}] }], totals }`

**`GET /unit-types`** (لم يكن مستخدماً): `total_units`، `base_rate_plan_id`، `base_rate_plan.min_rate`، و`low/high_weekdays_rate`.
- ملاحظة: `occupancy.max_adults` = 2 لكل الأنواع، بينما `quote` يقبل 4 بالغين. لذلك **لا نستورده**.

**`POST /reservations`**: زائر يحفظ حجوزات الـ API بحالة `confirmed` (حتى مع `status=new`). عدم الدفع يظهر في `payment_status=unpaid`.

## أدوات اختبار جديدة
- `WA_SEND_ONLY_TO=9627...` في `.env`: الأرقام خارج القائمة لا يُرسل لها شيء فعلياً، ويُطبع المحتوى والأزرار في السجل `🧪 [WA غير مُرسل]`. **اتركه فارغاً في الإنتاج.**
- `scripts/simulate.js`:
  - `--image <ملف> [تعليق]`
  - `--audio <ملف.ogg>`
  - `--tts "نص"`: يولّد رسالة صوتية ويحتاج ffmpeg.
  - الوسائط تُرفع إلى Meta للحصول على media id حقيقي، فيمر السيرفر بنفس مسار التحميل والتفريغ والتحليل.

## نقاط مفتوحة تحتاج قرارك
1. **العملة في زائر**: كل حجوزات الـ API (`booking_engine`، ومنها حجوزات النظام القديم `WA_BOOK_...`) محفوظة بعملة `sar` رغم إرسال `JOD`. المبالغ صحيحة، لكن رمز العملة خاطئ. يبدو إعداداً افتراضياً في زائر لقناة الـ API. **اسأل دعم زائر.**
2. **الحد الأدنى من زائر**: صار `minRate` = `min_rate` من خطة السعر في زائر: 68 للشقق، و35 أو 40 للاستوديوهات. في الاستوديوهات `min_rate` = سعر أيام الأسبوع، **فلا يوجد هامش تفاوض في أيام الأسبوع** إلا في نهاية الأسبوع (حد الخصم 15%). عدّله من صفحة «الأسعار والتفاوض» إن أردت هامشاً.
3. **وحدة «تجريب فقط» مفعّلة** في قواعد الأسعار، فقد يعرضها الـ AI على عميل حقيقي. **عطّلها من صفحة الأسعار قبل التشغيل الفعلي.**
4. **موظف «المدير» بالرقم 962790000000** (رقم افتراضي من مثال الإعدادات) كان يستلم كل الموافقات والتصعيدات. **عطّلته** ولم أحذفه. احذفه من صفحة الموظفين إن لم يكن له استخدام.
5. **نقاط زائر غير الموثقة** (الوصل المالي، تسجيل الوصول والمغادرة، الأرصدة) ما زالت تُرسل تنبيهاً يدوياً. زائر سيبقى `paid=0` حتى تُضبط نقطة الوصل.
6. **«حجوزات جديدة» وتوقيت الحجز المسبق**: زائر لا يرجع تاريخ إنشاء الحجز، فالحجوزات تُحسب حسب تاريخ الوصول، ومتوسط الحجز المسبق فارغ. الحل: أن يضيف زائر `created_at`، أو أن يحفظ النظام لقطة يومية للمحجوز.
7. **قاعدة البيانات اسمها `test`** لأن رابط `MONGODB_URL` بلا اسم قاعدة. لا مشكلة الآن، لكن غيّره إلى `/sahil` إن أردت فصلها (يتطلب نقل البيانات).
8. **الدراي كلين** لم يُختبر (يكتب في برنامج المغسلة).
9. **الرد عند تعطل Gemini** (آخر بند في السيناريو 9) لم يُختبر.
