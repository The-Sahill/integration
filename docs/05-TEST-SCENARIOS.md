# 7) سيناريوهات الاختبار

## قبل البدء: بيانات تجريبية
- **موظفون**: أنت بدور مدير. رقم آخر بدور استقبال. رقم ثالث بدور مالية. رقم رابع بدور صيانة. رقم خامس بدور تدبير منزلي.
- **نوع وحدة** باسم "شقة غرفتي نوم" ببيانات: unit_type_id من زائر، الأساسي 70، نهاية الأسبوع 85، الحد الأدنى 60، أقصى خصم 15%، الخطوات 5 و10 و15. وأسماء بديلة: "غرفتين"، "شاليه 3".
- **مخزون**: صنف "مناشف" بكمية 50 وحد تنبيه 10.
- **اختبارات الوحدة**: شغّل `cd backend && npm test`. يجب أن تنجح كلها: حساب الليالي، المواسم، الحد الأدنى، خطوات التفاوض، توقيع Meta وزائر، توحيد الأرقام.

> **بالأسعار الحقيقية من زائر** (بدل الأرقام أعلاه): شقة غرفتين، الخميس ← السبت = 70 + 90 = **160**، والحد الأدنى max(68×2، 160×0.85) = **136**. التسلسل المتوقع: 160 ← 152 ← 144 ← 136 (آخر سعر) ← تحت الحد.
> للاختبار بأرقام وهمية دون إرسال فعلي استخدم `WA_SEND_ONLY_TO` (انظر `03-SETUP.md`). وللكتابة في زائر استخدم وحدة **«تجريب فقط»**.
> نتائج آخر جولة وإصلاحاتها في [`07-TEST-RUN.md`](07-TEST-RUN.md).

## 1) عميل يحجز ويفاوض (نص)
| الخطوة | ترسل من رقم عميل | المتوقع |
|---|---|---|
| 1 | «مرحبا» ثم «بدي شقة» ثم «لـ 4 أشخاص» خلال ثانيتين | **رد واحد** فقط بعد 4 ثوانٍ (التجميع)، مع علامة "تمت القراءة" ومؤشر الكتابة فوراً |
| 2 | «من الخميس الجاي للسبت» | يحوّل التواريخ ويستدعي `check_availability` لهذه التواريخ فقط، ثم يعرض شقة الغرفتين بسعر 170 (85+85). المرحلة في اللوحة تصبح **تم عرض السعر** |

| 6 | «120 أو بلاش» | الحالة `below_floor`، فيعرض رفع الطلب للإدارة |
| 7 | «اوكي ارفعها» | يصل المدير طلب فيه زري "✅ موافق 120" و"❌ رفض" (انظر السيناريو 6) |
| 8 | (بعد موافقة المدير) «تمام احجزلي، اسمي أحمد محمد» | `create_hold` يرجع حجزاً مبدئياً B-XXXX بسعر 120 مع تعليمات الدفع (كليك/بنك). المرحلة: **بانتظار الدفع**. لا يقول "مؤكد" |
| 9 | لا ترد لمدة ساعة | المتابعة الآلية ترسل "تذكير لطيف" بإرسال الإيصال. خارج نافذة 24 ساعة يُستخدم قالب `payment_reminder` |

## 2) موظف يأمر بالصوت
| الخطوة | ترسل من رقم موظف استقبال | المتوقع |
|---|---|---|
| 1 | 🎤 «احجز شاليه 3 من الخميس للسبت باسم أحمد 0791234567 بسعر 150» | يُفرَّغ الصوت ويُحفظ النص مع الرسالة (يظهر في اللوحة مع مشغل الصوت). تصل رسالة إعادة صياغة: «📝 حجز جديد في زائر: الوحدة شقة غرفتي نوم...» مع زري **✅ نعم، نفّذ** و**❌ لا** |
| 2 | اضغط «✅ نعم» | تحقق نهائي من التوفر، ثم الإنشاء في زائر، ثم رد «تم إدخال الحجز في زائر (رقم)...». العميل 0791234567 يصله تأكيد الحجز. يُسجَّل الحدث في **سجل التدقيق** |
| 3 | 🎤 «احجز نفس الشي بسعر 100» | **رفض**: «السعر 100 أقل من الحد الأدنى المسموح (145) — يحتاج موافقة المدير». المدير يستطيع تنفيذه |
| 4 | «شو الشواغر نهاية الأسبوع؟» | قائمة بالأنواع المتاحة والأسعار لليلتي الخميس والجمعة |
| 5 | «أكّد دفع حجز أحمد» (من رقم المالية) | زر تأكيد، ثم الإدخال في زائر والتأكيد للعميل |
| 6 | «أكّد دفع حجز أحمد» (من رقم الصيانة) | لا تظهر الأداة لهذا الدور، فيرد بأنه غير مسموح |
| 7 | 🎤 «صرفنا 10 مناشف» (تدبير منزلي) | `adjust_inventory` بقيمة -10، فتصبح المناشف 40 |
| 8 | 🎤 «صرفنا 35 مناشف» | تصبح 5، فيصل تنبيه "📦 تنبيه مخزون" للمدير والتدبير المنزلي |

## 5) الدفع بإيصال
| الخطوة | المتوقع |
|---|---|
| العميل (بانتظار الدفع) يرسل صورة إيصال كليك | يقرأ Gemini المبلغ والتاريخ والاسم. يرد على العميل «استلمنا الإيصال ✅ قيد المراجعة». يصل موظفي المالية والمدير ملخص فيه المبلغ المطلوب مقابل المقروء، و⚠️ إذا كان المبلغ أقل، **مع صورة الإيصال** وزري **✅ تأكيد الدفع** و**❌ رفض** |
| المالية تضغط «✅ تأكيد» | تحقق نهائي من التوفر، ثم `POST /reservations` في زائر، ثم رسالة للعميل «✅ تم تأكيد حجزك... رقم الحجز...». المرحلة تمر بـ تم الدفع ← مُدخل في زائر ← مؤكد |
| إذا رفض زائر الحجز | تصبح حالة الحجز "فشل — يحتاج تدخل" ويصل تنبيه 🚨 للمدير. من صفحة "الحجوزات والدفع" يوجد زر **إعادة الإدخال** |
| المالية تضغط «❌ رفض» | يُبلَّغ العميل بلطف ويُطلب منه إعادة الإرسال |

## 7) الدفع بالبطاقة (إذا فعّلت `ZAAER_CHECKOUT_ENABLED`)
- العميل: «بدي أدفع فيزا» ← رابط دفع من زائر.
- محاكاة الـ webhook محلياً بعد إنشاء checkout حقيقي (استبدل SECRET و REF):
```bash
BODY='{"result":{"status":"paid","reference_number":"B-XXXXXX"}}'
TS=$(date +%s)
SIG=$(printf "%s.%s" "$TS" "$BODY" | openssl dgst -sha256 -hmac "WEBHOOK_SECRET" | sed 's/^.* //')
curl -X POST "http://localhost:4000/webhook/zaaer/payments?ref=B-XXXXXX" \
  -H "Content-Type: application/json" -H "X-Webhook-Event: payment.paid" \
  -H "X-Webhook-Event-Id: evt_1" -H "Idempotency-Key: evt_1" \
  -H "X-Webhook-Timestamp: $TS" -H "X-Webhook-Signature: $SIG" -d "$BODY"
```
- المتوقع: الإدخال في زائر والتأكيد للعميل. **إعادة نفس الطلب** ترجع `{"duplicate":true}` بدون أي تنفيذ.

## 8) الديلفري والدراي كلين

## 10) التقرير الصباحي
- من اللوحة: **الرئيسية** ← **أرسل الآن**، أو انتظر الساعة المضبوطة (8 صباحاً افتراضياً).
- المتوقع: رسالة للمدير فيها الإشغال، والوصول والمغادرة اليوم، والحجوزات الجديدة، والمدفوعات المعلقة، والتذاكر المفتوحة، ونسبة نجاح التفاوض.

## 11) سيناريوهات التحديث الثاني
| السيناريو | المتوقع |
|---|---|
| عميل يصل لـ `create_hold` | الحجز يظهر في زائر فوراً برقم booking_id = B-XXXX، **بدون أي وصل مالي**. في صفحة "الحجوزات والدفع" يظهر رقم زائر، والمدفوع = 0 |
| انتهاء المهلة بدون دفع | الحجز يُلغى في زائر (`status=cancelled`)، وحالته المحلية تصبح "منتهي" |
| المالية تؤكد الإيصال | لا يُعاد إنشاء الحجز في زائر. يُنشأ الوصل المالي (أو يصل للمالية تنبيه "مطلوب إصدار وصل" إن لم تُضبط النقطة)، ويصل العميل تأكيد الحجز |
| 🎤 استقبال: «سجّل وصول أحمد شقة 7» | زرا نعم/لا، ثم Check-in، ثم ترحيب للنزيل برقم شقته، والمرحلة تصبح "نزيل مقيم" |
| 🎤 استقبال: «عدّل حجز أحمد لحد الأحد» | زرا نعم/لا، ثم التعديل في زائر (`status=modified`) بالسعر الجديد، ثم رسالة للنزيل |
| 🎤 استقبال: «سجّل مغادرة أحمد» وعليه متبقٍ | رفض مع ذكر المبلغ المتبقي |
| 🎤 محاسب: «سجّل وصل لأحمد 50 كاش» | زرا نعم/لا، ثم وصل في زائر، ثم ردّ بالمتبقي |
| 🎤 مدير: «أعطِ سارة (تدبير منزلي) صلاحية تأكيد الدفع لمدة 8 ساعات» | تأكيد ثم منح. سارة تستلم إيصالات الدفع حتى انتهاء المدة، ثم تُسحب تلقائياً |
| مالك على واتساب: «قارن هذا الشهر بالماضي» | جدول مختصر: الإشغال، الإيراد، ADR، الحجوزات، الإلغاء، المحصّل، حجوزات AI مع ▲▼ |
| مالك: «شو المخاطر وشو تنصحني؟» | 🔴🟠🟡 المخاطر، ثم 5 نصائح مرقّمة |
| اللوحة ← التحليلات ← مقارنة الفترات ← شهر بشهر ← السابق | جدول بالمؤشرات العشرين مع التغيّر الشهري والسنوي |
| اللوحة ← الـ AI والـ Prompt ← تعليمة "اقترح دائماً شقة الغرفتين للعائلات فوق 4" ← تجربة | الرد التجريبي يلتزم بالتعليمة بدون تنفيذ أي حجز |
| الإعدادات ← طرق الدفع ← تعطيل كليك | تعليمات الدفع التالية لا تذكر كليك، والـ AI لا يعرضه |
